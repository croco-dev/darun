# 다른 Visual

실제 서비스의 화면·플로우·앱을 탐색하는 Next.js 프론트엔드입니다.

- 필터 없는 메인은 앱마다 최신 공개 스크린샷 한 장만 표시합니다. 실제 앱 로고(모바일 36px·데스크톱 40px)와 이름(16px)을 위에 배치하며, 앱 이름은 앱 상세로, 화면 이미지는 화면 상세로 연결됩니다. 검색·유형·플랫폼·서비스 필터를 적용하면 전체 화면을 탐색합니다.
- `/apps`는 스크린샷이 있는 앱만 표시하며 앱 이름·slug로 검색합니다. 스크린샷이 없는 앱의 상세 URL은 유지합니다.
- 화면 검색은 플랫폼·화면 유형·서비스 필터와 격자/목록 보기를 지원합니다.
- 플랫폼이 미분류된 화면은 원본 이미지 비율로 표시합니다. 플랫폼·화면 유형 필터는 API에 저장된 분류값을 사용하며, 이 프론트엔드 변경은 프로덕션 분류 데이터를 수정하지 않습니다.
- 앱 상세 설명은 HTML을 정제한 뒤 제목·목록·문단으로 표시합니다. 스크립트·이벤트 핸들러·위험한 URL과 인라인 CSS는 제거합니다.
- 플로우 필터 초기화는 검색어·플랫폼·유형·서비스 조건을 모두 제거합니다.
- 플로우 상세는 썸네일과 좌우 방향키로 단계를 이동하며, `?step=2`처럼 특정 단계를 공유할 수 있습니다.
- 상세 화면에서 링크를 복사하고 스크린샷을 확대할 수 있습니다.
- 헤더 검색과 `⌘K`/`Ctrl+K`로 검색에 접근할 수 있습니다. 검색 라벨은 현재 화면·앱·플로우 경로에 맞춰 표시되며, 건너뛰기 링크는 페이지의 공통 `main` 본문으로 이동합니다.
- `/collections`에서 이름을 붙인 컬렉션을 만들고 화면·플로우·앱을 저장하거나 제거할 수 있습니다. 컬렉션은 현재 브라우저의 `localStorage`에만 저장되며 계정·기기 간 동기화되지 않습니다. 브라우저 데이터를 삭제하면 컬렉션도 삭제됩니다.

메인과 앱 목록은 기존 스크린샷 API의 모든 커서 페이지를 읽어 앱별로 묶습니다. 첫 페이지에 없는 앱도 포함하며, API에 앱별 집계 기능이 생기면 이 메타데이터 순회를 대체할 수 있습니다.

## 로컬 실행

`.env.sample`의 환경 변수와 GraphQL API가 필요합니다. 개발 서버는 `pnpm --filter visual-web dev`로 실행하며 기본 포트는 `3002`입니다.

## 검증

`pnpm --filter visual-web lint`, `pnpm --filter visual-web typecheck`, `pnpm --filter visual-web test`로 검사합니다. 컬렉션 회귀 테스트는 저장 실패·손상 데이터·안전하지 않은 링크·중복 항목·새로고침 후 복원을 검증합니다. 앱 설명 테스트는 실제 컴포넌트를 렌더링해 HTML·일반 텍스트·빈 값과 악성 스크립트·CSS 제거를 검증합니다.

AI 의미 검색·스크린샷 OCR·Figma 연동은 제공하지 않습니다. 화면과 플로우 검색은 기존 GraphQL API의 검색 범위를 따릅니다.
